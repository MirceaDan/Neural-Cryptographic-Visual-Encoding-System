# Task: Investigate NCVES — Can a Neural Network Instance Act as Its Own Cryptographic Key?

## Context

I am investigating a concept called **Neural Cryptographic Visual Encoding System (NCVES)**.

The central hypothesis is that the specific trained neural network instance—not a separately supplied conventional cryptographic key—acts as the secret required to decode a visual code.

Given a message \(m\), an encoder instance \(E_{\theta_s}\) generates a visual code:

\[
I=E_{\theta_s}(m)
\]

After physical-channel degradation \(C\), the corresponding decoder instance \(D_{\phi_s}\) should recover the message:

\[
D_{\phi_s}(C(I))\approx m
\]

A competing party may possess the same training dataset, architecture, source code, and training procedure, but independently retrain the network. The resulting weights will generally differ from the original instance.

The core hypothesis is that an independently trained or imitated model cannot reliably decode codes generated by the original instance, even if it has access to the same training data.

This is a research hypothesis, NOT an established security property. Do not assume it is true.

## Objectives

### 1. Audit the existing repository

Inspect the entire repository before making changes.

- Identify the existing encoder, decoder, training pipeline, data format, checkpoints, and evaluation scripts.
- Determine whether the current implementation can support an instance-dependent encoding experiment.
- Identify relevant existing components that can be reused.
- Preserve the existing implementation and work on a separate branch or isolated experimental directory.
- Do not overwrite existing checkpoints, datasets, or working experiments.

Produce a concise architecture and implementation report before starting modifications.

### 2. Establish a valid baseline

Implement or adapt the smallest viable neural visual communication system.

Requirements:
- Encode a known binary message into a visual representation.
- Decode it using the corresponding trained model instance.
- Include a differentiable channel during training and realistic image degradation during evaluation.
- Test digital transmission separately from physical-channel simulation.
- Record bit error rate (BER), exact-message recovery rate, payload capacity, and decoding latency.

Do not introduce conventional encryption as a substitute for the hypothesis being tested. Clearly distinguish any optional cryptographic baseline from the primary experiment.

### 3. Test whether the model instance acts as the secret

Train an original encoder-decoder pair \(s\), then generate a held-out test set of visual codes.

Evaluate the following decoder configurations:

**A. Original instance**
- Use the original decoder \(D_{\phi_s}\).
- Measure legitimate decoding accuracy and robustness.

**B. Independent retraining**
- Retrain the same architecture on the same training data using different random seeds and initializations.
- Evaluate whether these independently trained decoders can decode codes generated by the original encoder.
- Repeat across multiple independently trained instances.

**C. Same architecture, different training conditions**
- Test alternative initialization, training order, and reasonable hyperparameter variations.
- Determine whether compatibility depends on exact weights, a shared learned representation, or merely the architecture and training distribution.

**D. Decoder imitation / model stealing**
- Investigate whether a substitute decoder can be trained using available code-message pairs, observed visual codes, or query access to the original encoder, depending on the threat model.
- Separate attacks requiring labeled examples from attacks requiring only unlabeled codes.
- Report the attacker's assumptions and data requirements explicitly.

**E. Physical robustness**
- Repeat legitimate and unauthorized decoding tests after printing and photographing, or using a well-documented physical-channel simulation if physical equipment is unavailable.
- Include blur, perspective distortion, illumination changes, sensor noise, compression, and partial occlusion where appropriate.

### 4. Investigate the role of model-specific statistical behavior

The original intuition was that independently trained models may develop different statistical behaviors, including different reconstruction errors or artifact patterns.

Test whether any such differences can provide a stable, controllable compatibility mechanism.

Do not assume that model hallucinations are cryptographic secrets. Distinguish:
- numerical differences between weights;
- behavioral differences between model instances;
- measurable model fingerprints;
- actual inability of an unauthorized decoder to recover the payload.

Determine whether a fingerprint is genuinely necessary for decoding or merely identifies the model after the fact.

### 5. Define rigorous metrics

At minimum, report:

- Legitimate decoder BER and exact-message recovery rate.
- Unauthorized decoder BER and exact-message recovery rate.
- False acceptance rate and false rejection rate, with precise definitions.
- Performance after physical-channel degradation.
- Results across multiple random seeds and independently trained instances.
- Performance of any substitute decoder trained by an attacker.
- Computational and storage costs.
- Confidence intervals or appropriate uncertainty estimates.

Include a table comparing original-instance decoding against every unauthorized-decoder scenario.

A high legitimate decoding accuracy alone is insufficient. The essential result is a reproducible separation between legitimate and unauthorized decoding.

### 6. Investigate leakage and security limitations

Explicitly test whether the proposed mechanism fails when:
- the training dataset is known;
- the architecture and training code are public;
- multiple codes generated by the original encoder are observable;
- known message/code pairs are available;
- the original model weights are compromised;
- an attacker can train a substitute decoder.

Do not claim information-theoretic or cryptographic security from empirical accuracy results alone.

If the original weights are the secret, explain the consequences of weight theft. Distinguish model-instance compatibility from a cryptographically secure key-management system.

### 7. Compare with relevant prior art

Investigate at least:

- StegaStamp: https://openaccess.thecvf.com/content_CVPR_2020/html/Tancik_StegaStamp_Invisible_Hyperlinks_in_Physical_Photographs_CVPR_2020_paper.html
- Universal Perturbation-based Secret Key-Controlled Data Hiding: https://arxiv.org/abs/2311.01696
- Relevant work on neural network fingerprinting, model stealing, learned visual communication, and neural steganography.

Identify what is already known and whether this experiment tests a technically distinct mechanism.

Do not assert patent novelty. Produce a technical comparison of mechanisms, assumptions, and experimentally demonstrated properties.

## Experimental discipline

- First inspect the repository and propose the experiment.
- Implement the smallest meaningful experiment before attempting a sophisticated architecture.
- Use fixed, documented train/test splits and prevent data leakage.
- Keep the original instance and its checkpoints immutable.
- Run multiple seeds; do not select only favorable results.
- Save configurations, checkpoints, logs, metrics, and scripts needed to reproduce results.
- Report negative results honestly.
- Do not silently change the hypothesis to make the experiment succeed.

## Required deliverables

1. Repository audit and proposed experimental design.
2. A minimal runnable implementation or a clear explanation of why the current repository is unsuitable.
3. Reproducible scripts for training, encoding, decoding, and evaluation.
4. A results table covering legitimate decoding, independent retraining, and substitute-decoder attacks.
5. A written interpretation explaining what the experiments establish and what they do not establish.
6. A final verdict choosing one of:

   - **Partially supported:** legitimate decoding works, but one or more realistic attacks defeat the mechanism.
   - **Not supported:** independently trained or substitute models decode the codes too successfully, or legitimate decoding is not robust.
   - **Inconclusive:** insufficient experiments or reproducibility to decide.

## Most important question

Can we demonstrate that a visual code generated by one particular trained neural network instance can be decoded robustly by its corresponding decoder, but not by independently trained or imitated models—even when those models have the same training data, architecture, and training code?

If the answer is yes, identify the exact mechanism responsible for this separation and quantify it.

If the answer is no, explain why the original intuition fails and whether a narrower, technically meaningful research direction remains.

Prioritize falsifying the hypothesis over confirming it. Do not claim security, novelty, or patentability without evidence.

# NCVES — Controlled Cross-Decoding Experiment and Patentability Evidence

## Mission

Investigate the central hypothesis behind the Neural Cryptographic Visual Encoding System (NCVES):

**A jointly trained student–teacher pair learns a model-specific visual encoding that its associated teacher can decode reliably, while independently trained teachers cannot recover the same messages with comparable accuracy, even when they use the same architecture, training data, and training procedure.**

We need experimental evidence that can be presented to a patent attorney to distinguish the proposed mechanism from conventional neural image encoding, StegaStamp, HiDDeN (2018), and explicit-key-controlled data hiding.

Do not assume the hypothesis is true. Your job is to try to falsify it.

The ablation is finished and the verdict is Outcome 1: no demonstrated distinction between NCVES and conventional joint training. The HiDDeN-style comparison itself is invalid, because that baseline never learned to decode its own codes. The full report is experiments/hidden_ablation/REPORT_ablation.md. Earlier results were not modified.

 - Cross-decoding: every group that decodes its own codes fails on independently trained decoders. Off-diagonal BER is about 0.50 and exact-message accuracy is 0, with no cross-decoding successes in any group. This includes the key-conditioned encoder with no separation loss (key0), which has no NCVES-specific component, so ordinary joint training plus random initialization explains the effect.
 - HiDDeN-style baseline: diagonal BER was 0.23–0.38 across eight models (five at λ_img 0.7, three at 0.05), so its small gap says nothing about secrecy. It is an adapted baseline, not a faithful reproduction. It also has a large capacity mismatch (9.7k vs 1.08M parameters), and I read only the HiDDeN abstract.
 - Substitute-decoder attack: about 100 labeled pairs break NCVES, key0 and key1 alike, at roughly 0.90 exact on clean images and 0.76–0.81 under the simulated degradation. At 500 pairs NCVES is at about 1.000. I did not attack a converged conventional baseline, because I never obtained one.
 - Key-separation loss (the only identifiable mechanism): it makes random wrong keys fail for the key-conditioned encoder, but one bit-flipped key still decodes with BER 0.000. This is an explicit-key effect, not an instance effect. It rests on two seeds per variant, so no confidence interval is available.
