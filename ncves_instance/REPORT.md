# NCVES instance-compatibility experiment — report

All numbers come from files in `results/` (generated by the scripts here). Nothing in the repo root was modified.
Tables: `results/tables.md`. Raw: `evaluate.json` (matrices), `attacks/*.json`, `attack_unlabeled.json`, `analysis.json`, `ablation_fixed_encoder.json`, `audit_original.json`. First-run copies kept in `results/_prev_first_run/` (evaluate/analysis were re-run only to add the `C_width2` run that finished after the first run).

## 1. Audit of what existed
* Repo root: `train.py` (key-conditioned MLP encoder, 3-conv decoder, 3x3 blur + noise channel, key-separation loss) and `NCVES.pdf` (spec). No data, checkpoints, logs or evaluation existed.
* `audit_original.py` imports the **unmodified** `train.py` objective and trains it for its own 1000 steps: BER with the correct key = 0.471, with a wrong key = 0.472, i.e. it never learns to decode at all (loss plateaus ≈0.62 because the negated-BCE "separation" term is unbounded and fights the reconstruction term). The repo is therefore unsuitable as a baseline; it also uses an explicit key input, which is a different mechanism from the instance-only hypothesis. It was left intact.
* New code (isolated in `experiments/ncves_instance/`): `common.py` (splits, models, channels, metrics), `train_instance.py`, `evaluate.py`, `attack_train.py`, `attack_unlabeled.py`, `analysis.py`, `ablation.py`, `make_report.py`, `run_train.sh`, `run_attacks.sh`; logs in `logs/`; checkpoints+configs+SHA256 in `runs/` (train_instance refuses to overwrite).
* Leakage check: 44,000 unique 24-bit payloads (+CRC-8 = 32 coded bits) split once with a fixed seed into train 20k / attacker 20k / test 2k / val 2k; `make_splits` asserts the four sets are disjoint. Defender training uses only `train`; attacks use only `attacker`; all reported results use `test`. Weak point: only the *payload* distribution is controlled, not the image content (images are generated, so no image dataset exists).
* Architecture: encoder 32 bits → MLP → 3 transposed convs → 64×64 gray image (1.08 M params); decoder 4 strided conv blocks + MLP (0.33 M). Training: joint, BCE, 3000 steps Adam/OneCycle, batch 128, differentiable channel (occlusion, homography, blur, gamma/contrast/brightness/gradient, noise, straight-through JPEG-DCT) with severity curriculum. Evaluation channel is an independent cv2/numpy implementation (real warp, blur, JPEG, print-tonal proxy). Levels: digital, L1/L2/L3 = severity 0.33/0.66/1.0.
* Seeds: `orig` (init/data/noise seed 0); B_r1..B_r5 (all three seeds = i); C variants change one factor at a time.

## 2. Pre-specified criteria (stated honestly: written after the runs were launched, before interpreting the cross matrix)
Supported iff: (a) legitimate exact-message rate ≥0.95 at L2; (b) every independent decoder (B) has BER ≥0.45 and CRC-accept ≈ chance (2⁻⁸); (c) a labeled-pair substitute with ≤100 pairs does not reach exact ≥0.5. Mechanism claim additionally requires (d) the gap to vanish when decoder is decoupled from a learned encoder in a control and (e) no cheap attack. Definitions: FRR = 1−CRC-accept of the legitimate decoder; FAR = CRC-accept of an unauthorized decoder (chance 0.0039; "accepted and wrong" is reported in JSON).

## 3. Results (2,000 held-out messages, 32 bits each)
**A/B cross matrix, 6 independent pairs (orig + B1–B5), BER, digital** (full 14×14 incl. C runs in `tables.md`; L2 matrix in `evaluate.json`):

| enc \ dec | orig | B1 | B2 | B3 | B4 | B5 |
|---|---|---|---|---|---|---|
| orig | **0.000** | 0.494 | 0.495 | 0.505 | 0.491 | 0.477 |
| B1 | 0.495 | **0.000** | 0.501 | 0.502 | 0.470 | 0.514 |
| B2 | 0.493 | 0.503 | **0.000** | 0.501 | 0.494 | 0.502 |
| B3 | 0.494 | 0.496 | 0.499 | **0.000** | 0.494 | 0.487 |
| B4 | 0.498 | 0.472 | 0.500 | 0.495 | **0.000** | 0.495 |
| B5 | 0.477 | 0.508 | 0.511 | 0.507 | 0.496 | **0.000** |

* Diagonal BER 0.000, exact 1.000 (digital); L2: diag BER 0.00008, exact ≥0.994 (orig 0.999). Off-diagonal mean BER 0.4956 (min 0.470); L2 0.4954. Off-diagonal exact-message rate = 0/2000 for all B decoders on orig codes (Wilson upper bound ≈0.0019 per decoder). CRC-accept (FAR) of B decoders 0.002–0.006 ≈ chance 0.0039.
* Paired per-encoder comparison (off-diagonal mean − diagonal, n=6 pairs): +0.4956, 95% t-CI [0.492, 0.499], paired t p=3e-12, Wilcoxon p=0.031 (the minimum possible for n=6). BER CIs inside a cell are message-level bootstraps; between-pair inference uses pairs as the unit.
* Legitimate orig, L1/L2/L3: BER 0 / 0.0000 / 0.0030; exact 1.0 / 0.999 / 0.944. Single-factor s=1: only perspective hurts (BER 0.0135, exact 0.837); blur/illumination/noise/JPEG/print-proxy/occlusion exact ≥0.997. (Simulation only; no physical print/photo was performed.)
* Cost: payload 32 bits (24 info) in 4096 px = 0.0078 bit/px; decode 0.26 ms/code, encode 0.42 ms (1 CPU thread); checkpoints 4.3 MB (enc) + 1.3 MB (dec); training 566 s on a loaded shared CPU.

**C: variation of one factor (decoder applied to orig codes, digital BER / exact):**
| decoder | BER | exact |
|---|---|---|
| different init, same data order/noise (C_diffinit_samedata) | 0.496 | 0 |
| lr ×2 / ×0.5, batch 64, 1500 steps, width ×2 (different init seeds) | 0.488–0.503 | 0 |
| **same init seed, different data order (C_sameinit_diffdata)** | **0.067** | **0.142** |
| **same init seed, different channel-noise seed (C_onlynoise_seed)** | **0.043** | **0.269** |

Same-initialization retrains produce codes correlated 0.61–0.65 with the original's (vs ≈0.00–0.02 for different inits) and partially decode them (also at L2: exact 0.09–0.17). So the effect is **determined by the random initialization**, not by data, order or hyperparameters; a party who knows the init seed (or the RNG/framework default) recovers a large part of the capability. Weight-space: linear interpolation orig→B1 fails at α=0.5 (BER 0.24) and is chance beyond 0.75; multiplicative-Gaussian weight noise up to 10 % of per-tensor std costs nothing, ~100 % noise gives BER 0.22 — the decoder is not exact-weight-brittle, but separate basins are mutually incompatible.

**D: substitute decoder (attacker knows architecture/code/channel family; trained from scratch on (code, message) pairs from the orig encoder, drawn from the disjoint attacker pool; trained on clean codes passed through the training channel, i.e. both clean and distorted; tested on held-out test codes; 3 attacker seeds, 3000 steps ≈ 8 min CPU):**
| labeled pairs | BER digital | exact digital (max of 3 seeds) | BER L2 | exact L2 |
|---|---|---|---|---|
| 25 | 0.203 [0.187,0.219] | 0.001 | 0.208 | 0.0015 |
| 100 | 0.0034 [0.0021,0.0046] | 0.916 | 0.0072 | 0.816 |
| 500 | 0.0000 | 1.000 | 0.0001 | 0.999 |
| 2500 / 20000 | 0.0000 | 1.000 | 0.0001 | 0.999 |
Warm start from another instance's decoder gives no advantage (25: 0.200; 100: 0.0036). A wider decoder (w2) with 2500 pairs: BER 0. **Defeated with ≈100 labeled pairs**, with an architecture-matched decoder; 25 pairs give BER 0.20 (far from chance 0.5 but not decoding).
Unlabeled attacks: with zero labels, PCA/autoencoder bit extraction is chance (BER 0.50) — the code is not blindly decodable. But PCA latents + only 32 labels give BER 0.023 digital (exact 0.52), 100 labels give exact 1.000 (digital) / 0.77 (L2), 1000 labels 0.989 (L2). The learned code is essentially a near-linear map of the message to pixels, trivially probeable.

**Weight theft / fingerprints (analysis.json):** a small CNN identifies which of 13 instances produced a code with 100 % (digital) / 94.7 % (L2) accuracy (chance 7.7 %) — instance fingerprints are real and detectable, but this is identification, not a decoding barrier. Swapping the mean "fingerprint" image of B1 into the orig code, or removing it, does not change orig's decoding (BER 0.000), and B1 codes shifted to orig's mean still fail (0.49): the mean fingerprint is neither necessary nor sufficient; compatibility is in the encoder–decoder function, not in a separable artifact. Decoder-only forgery: with orig decoder weights and no encoder, gradient-optimised images are decoded by orig with BER 0.000 digital / 0.0075 at L2, while B1/B2 decode them at chance (0.50/0.49); a fingerprint classifier labels 73 % of these forgeries as genuine orig codes (pixel MSE to real codes 0.054) — weight theft gives total compromise and forgery. Optional conventional-key baseline (msg XOR k before encoding, separate from the hypothesis): holder of the full orig instance but wrong k gets BER 0.344 (only the differing key bits are wrong — a single fixed k/k' pair, not a secrecy measure), right k gets 0.00003; it shows an explicit key is orthogonal to instance compatibility and is what actually withholds the message from a weight thief.

**E/ablation controls (ablation.py, 2 decoders per fixed encoder):**
* Non-neural hand-made 8×4 block-grid code (stand-in for a conventional code; no QR library/real QR decoder was used): two independently trained decoders both read it (BER 0.000 digital, 0.003 L2). Cross-decoding failure therefore does **not** occur for a fixed, public format; it appears only when the encoder's code is learned and private.
* Frozen random encoders (no joint training): both decoders stay at chance on both (BER 0.50), including decoders trained directly on it — the control is **uninformative** (random-encoder images carry too little message signal to learn within 2000 steps). A proper "unassociated-pair" ablation (e.g. learned encoder trained against a different frozen decoder, or encoder with decoder re-initialised mid-training) was **not executed**.

## 4. Status of experiments
Completed: audit; 6-pair cross matrix (digital + L2 full matrix; others per-condition for orig codes); same-data controls; C variations; labeled attacks (25–20000 pairs, 3 seeds); unlabeled+K-label attack; physical-channel *simulation* (7 single-factor + 3 combined levels); fingerprint, weight-noise, interpolation, weight-theft forgery; grid-code control; costs.
Partial: frozen-random-encoder ablation (uninformative); only one original encoder used for attacks (others' attack results not run); C variants are single instances (no CIs).
Unexecuted: real print-and-photo tests; real QR/barcode decoder baseline; HiDDeN/StegaStamp reimplementation; unassociated-pair ablation; query-access attacks with adaptive/chosen messages (only passive labeled pairs); attacks on a larger payload/bigger images; model-extraction by an attacker seeing only distorted photos; repeated attacker runs for other instances.

## 5. Interpretation
Established (within this toy setting, 32 bits, 64×64, simulated channel):
1. **Instance-specific encoding exists**: 5/5 independent retrains (and 5 hyperparameter variants with different inits) are at chance (BER ≈0.49, exact 0/2000, FAR ≈ chance) on the original's codes, while the matched decoder is exact (≥99.9 % at L2) — a reproducible, large gap (≈0.50 BER, paired p≪0.001), identical for digital and simulated-physical channels.
2. The mechanism is **joint learning from a random initialization**: code format ≈ symmetry-broken arbitrary basis (same-init retrains are partially compatible; mean-fingerprint is irrelevant). Public fixed formats show no gap.
3. Legit decoding is robust to simulated blur/noise/JPEG/illumination/print-proxy/occlusion; weakest to strong perspective.

Not established / refuted:
* **Resistance to substitute decoders is refuted**: ≈100 labeled pairs (a few minutes of CPU) give exact 0.82–0.92; 500 pairs give ≥0.999 at L2. Even unlabeled codes plus 100 labels suffice. The mapping is low-complexity, so an observer of a few code/message pairs (e.g. any protocol with known plaintext headers) breaks it. No weight access is needed.
* No security claim: this is obscurity of a learned format, not a key; there is no key space, rotation, or hardness argument; weight theft is total compromise; the retraining attack uses only public architecture; the 25-pair BER 0.20 shows only partial data-limited failure.
* Mechanism attribution (not complete): the gap's dependence on initialization is shown; the lack of a gap for a fixed grid code shows it needs a learned code; the missing unassociated-pair ablation leaves "ordinary joint-training symmetry breaking" as the full explanation — i.e. nothing here distinguishes the effect from what any jointly trained learned visual communication system (HiDDeN-/StegaStamp-style) would exhibit if independently trained decoders were tested. Those papers do not publish a cross-decoding matrix to compare against (not verified here by reimplementation); HiDDeN-type decoders are trained jointly and "non-matching decoder fails" is expected there too, but its function is detection/robustness, not secrecy. Explicit-key schemes (e.g. arXiv 2311.01696) provide a controllable secret input; this system has no controllable secret except the weights.

## 6. Verdict: **Partially supported**
A measurable, reproducible model-pair-dependent decoding effect exists (independent retraining → chance), but the most important attack (substitute decoder with ~100 labeled pairs) defeats it, same-init retrains partially decode, and key controls remain unexecuted. For the patent attorney: the defensible, narrower technical claims are (i) instance-bound *compatibility/identification* (e.g. 100 % attribution of code to generating instance, licensing/anti-mixing of encoder–decoder pairs) and (ii) a quantified separation under independent-retraining threat model only. A claim of secrecy/cryptographic security, or of distinction from jointly trained HiDDeN/StegaStamp-style systems on the basis of this evidence, is not supported. The highest-information next experiments: unassociated-pair ablation, real print/photo test, a real QR baseline, and a defense that raises the labeled-pair requirement (e.g. per-message randomized/keyed latent) evaluated against the same substitute attack.
